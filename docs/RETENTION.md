# 削除機能：内部実装済み・運用では実行不可

v0.1.1で将来用の内部処理を準備しました。通常のTamaruは調査専用のままです。

## 無効化の範囲

- Web画面に削除・退避・完全削除のボタンを追加していません。
- 削除を実行するAPIルートを登録していません。URLを直接指定しても404です。
- 起動コマンドに削除・退避・有効化の引数を追加していません。
- 管理者の設定画面・設定APIに削除を有効にする項目はありません。未知の設定キーは拒否します。
- 環境変数による有効化はありません。
- 公開窓口`DeletionService`の実行メソッドは、管理者・引数にかかわらず常に`DeletionDisabled`を返します。
- 日次・手動収集は、内部削除エンジンを生成も呼び出しもしません。
- 削除用の追加観測、退避フォルダの作成、削除用台帳の作成も、通常運用では行いません。

認証済み管理者向けの`GET /api/deletion/status`だけで実装状況を確認できます。常に`implemented: true`、`enabled: false`を返します。画面のボタンや有効化操作には接続していません。

Pythonコードを編集できるサーバー管理者まで制限する仕組みではありません。有効化にはアプリのコード変更が必要です。

## 準備した内部処理

内部モジュールは、隔離したテストからだけ呼び出しています。

1. **削除用の追加観測**：WindowsのファイルID・作成時刻・更新時刻・容量を記録。中身・ハッシュは読みません。別のファイルへ置き換わったり、記録した日時・容量が変わったり、観測間隔が36時間を超えたりした場合は、削除用の継続期間を数え直します。
2. **候補作成**：初回検出から30日以上、削除用の同一性観測も30日以上続き、最新の正常な収集で確認できたファイルだけを候補にします。最新観測が36時間より古いもの、読み取りエラーがある対象、対象から除外したものは処理しません。
3. **退避**：有効期限15分の候補一覧を再検証し、収集対象外の専用退避先へ移動します。同一ボリュームでの移動だけを使い、別ボリュームへのコピーや既存ファイルの上書きに切り替えません。
4. **完全削除**：退避後7日以上経った記録だけを照合して処理します。変更されたもの、台帳のパスが合わないもの、中断などで処理状況が不明なものは自動再処理せず、要確認として残します。

標準の内部上限は1回100ファイル・合計10GiBです。候補の退避と完全削除のそれぞれに上限を適用します。実行前後・スキップ・失敗を操作履歴へ記録します。フォルダの再帰削除は実装していません。

無効な現在のバージョンは、削除用の追加観測をまだ開始しません。将来有効化する際も、現在の一覧の滞留日数だけを使って直ちに削除せず、別途30日間の同一性観測が必要な設計です。

## Windowsでの実行直前の照合

対象ファイルをハンドルで開き、同じハンドルのファイルID・日時・容量を照合してから、Windowsの`SetFileInformationByHandle`で退避または削除します。照合後のパスのすり替えを避けるため、親フォルダもハンドルで保持します。

リンク・ジャンクション・再解析ポイント・複数ハードリンクは対象外です。使用中で必要な共有モードを確保できないファイルもスキップします。対応しないファイルシステムやSMBの操作を、単純なパス指定の削除に切り替えることはありません。

## 将来の有効化前に確認すること

現在は有効化手順を提供していません。実際に有効化する変更では、以下を具体化してから運用に組み込みます。

- 実際の共有上でのファイルID、ハンドル、退避・削除の動作確認。
- 退避先と対象の同一ボリューム条件、および退避先・退避ファイルを管理者だけが扱えるACL。
- 実行アカウントへの必要権限の付与と、復旧手順。Webからの復元機能は現在ありません。
- 候補の閲覧・確認と、認証・CSRF対策を含む実行操作。
- 件数・容量・時刻・停止条件・異常時の扱い、および初回の追加観測期間。

Windowsローカルの隔離テストは、実際の社内共有に対する動作確認の代わりにはなりません。
