# Tamaru 操作・運用手順書

対象バージョン: 0.2.0  
作成日: 2026年10月28日  
対象者: 自分のPCで使う管理者、社内LAN向けに設置・運用するサーバー管理者

## 1. 使い方を選ぶ

| 使いたい形                         | 始める場所                                             |
| ---------------------------------- | ------------------------------------------------------ |
| 自分のPCからだけ使う               | この資料の「2. ローカルで初めて起動する」              |
| 複数の管理PCからサーバーへ接続する | 「3. 社内LANで使う」と[LAN向け設置手順](DEPLOYMENT.md) |
| 既に起動できている                 | 「4. 対象フォルダを設定して収集する」                  |

Windows用の0.2.0のEXE一式を、書き込み可能なフォルダへ展開して使う。古いEXEではこの資料のローカル起動・階層表示を利用できない。画面下部のバージョンを確認する。

## 2. ローカルで初めて起動する

### 2.1 EXEで起動する

1. ZIPを展開し、`Tamaru.exe`をダブルクリックする。ZIPの中から直接実行しない。
2. 初回のコンソールで管理者IDを入力する。空欄ならIDは`admin`になる。IDは半角英数字で始まる3〜64文字で、半角英数字・`_`・`.`・`-`が使える。
3. 12〜256文字のパスワードを2回入力する。入力中の文字は表示されない。
4. ブラウザで`http://127.0.0.1:8765/`が開いたら、登録したID・パスワードでログインする。

既に管理者を登録した保存先では、2回目以降の登録は不要。ブラウザが自動で開かなければ、コンソールに表示されたURLを手動で開く。

この方法は自分のPCからだけ接続できる。証明書・サーバー設置・ファイアウォールの受信許可は不要。ログインはローカルでも必要になる。

### 2.2 保存先やポートを指定する

管理データは、指定しなければEXEと同じフォルダの`data`に作られる。EXEを別フォルダへ移す予定がある場合は、保存先を明示すると引き継ぎやすい。

以下はEXEがあるフォルダでPowerShellを開いて実行する例。

```powershell
.\Tamaru.exe --state C:\TamaruData local
```

8765番ポートが既に使われている場合は、別の番号を指定する。接続先もその番号に変わる。

```powershell
.\Tamaru.exe --state C:\TamaruData local --port 8766
```

ブラウザの自動起動が不要なら`--no-browser`を追加する。`--state`は`local`より前、`--port`と`--no-browser`は後に置く。

### 2.3 Pythonで起動する

Python 3.11以上を用意し、リポジトリのルートで実行する。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m tamaru --state C:\TamaruData local
```

以後の例の`Tamaru.exe`は、`.\.venv\Scripts\python.exe -m tamaru`に読み替えられる。

## 3. 社内LANで使う

LAN向けの設置は[DEPLOYMENT.md](DEPLOYMENT.md)に沿って行う。作業の順序は次のとおり。

1. アプリを置くフォルダと、管理データを置くローカルフォルダを決める。
2. 実行アカウントに、対象の共有への一覧・属性取得権限と、管理データへの書き込み権限を用意する。
3. サーバー上で初期管理者を登録する。
4. HTTPS証明書・秘密鍵を用意して直接公開するか、IISなどのTLS終端プロキシを設定する。
5. 接続を許可するHost名・管理PCのネットワーク範囲を指定して起動する。
6. 常駐させる場合は起動タスクを登録し、ログオフ中・サーバー再起動後も共有を収集できることを確認する。

初期管理者登録と直接HTTPSで起動する例:

```powershell
.\Tamaru.exe --state C:\TamaruData create-admin admin --display-name 管理者
.\Tamaru.exe --state C:\TamaruData serve `
  --host 0.0.0.0 --port 8765 `
  --allowed-host tamaru.example.local `
  --cert-file C:\TamaruCertificates\server.crt `
  --key-file C:\TamaruCertificates\server.key
```

ホスト名・証明書・保存先は設置先に合わせて置き換える。`local`はLAN公開用には使わない。プロキシ経由の具体的な起動・転送ヘッダーの設定と、Windowsタスクの設定項目は設置手順を参照する。

## 4. 対象フォルダを設定して収集する

1. 「対象フォルダ設定」を開く。
2. 調査するフォルダを1行に1つ入力する。

   ```text
   D:\受け渡し
   \\server\share\資料受け渡し
   ```

3. 日次収集を使う場合は「有効にする」と時刻を設定する。初期値は日本時間02:00。
4. 「設定を保存」を押す。
5. 「今すぐ収集」を押し、実行が終わるのを待つ。
6. 全体の件数・容量、対象フォルダ、「最近の収集」の結果を確認する。

収集対象とアプリ・管理データの保存先は分ける。例えばアプリが`D:\Apps\Tamaru`にある場合、その親の`D:\`全体は対象に登録できない。対象同士が親子になる設定もできない。

既に長く置いてあるファイルも、初回収集では0日から始まる。設定を保存しただけでは新しいファイルの一覧は収集されない。対象から外した記録は非表示になるが、保存先には残る。

## 5. 目的に合わせて一覧を見る

### 5.1 どのフォルダが容量を使っているか確認する

1. 「フォルダをたどる」を選ぶ。起動時の標準表示もこの画面。
2. 対象フォルダごとの容量・ファイル数を見る。
3. フォルダ名をクリックして中へ進む。
4. 子フォルダの配下合計と、現在のフォルダ直下のファイルを確認する。
5. 一覧の上のパンくずから、親フォルダや「すべての対象フォルダ」へ戻る。

フォルダは先に表示され、その後に直下ファイルが並ぶ。容量順でもフォルダとファイルは別グループになる。空フォルダは表示しない。

### 5.2 一番大きいファイルを探す

1. 全対象から探すなら「全ファイル一覧」を押す。特定のフォルダの中だけなら、そのフォルダを開いて「この配下の全ファイル」を押す。
2. 並べ替えで「容量が大きい順」を選ぶ。
3. ファイル名とパスを確認する。必要なら「対象フォルダ」や検索で絞り込む。

「全ファイル一覧」では対象フォルダと階層の選択が解除される。検索・日数条件は残るため、全ファイルを見たい場合は検索を空欄、日数を「すべての日数」にする。

### 5.3 長く置かれたファイルを確認する

1. 日数条件で「30日以上」などを選ぶ。
2. 必要なら「滞留日数が長い順」に並べ替える。
3. 所在と初回検出・最終確認を確認する。

同じ場所への上書きでは滞留日数は継続する。表示だけで削除可否を判断せず、ファイルの管理者に用途を確認する。Tamaruから削除する操作は提供していない。

### 5.4 集計と確認状態を読む

| 表示                 | 読み方                                                                   |
| -------------------- | ------------------------------------------------------------------------ |
| 画面上部の全体集計   | 設定中の全対象の合計。検索・日数条件では変わらない                       |
| フォルダの容量・件数 | 配下全体のうち、現在の検索・日数条件に合うファイルの合計                 |
| ページ下部の件数     | 表示行数。フォルダをたどる画面では、ファイル総数とは一致しない場合がある |
| 確認済み             | 公開済みの最新収集で確認できた記録                                       |
| 未確認               | 収集エラーなどで最新の確認ができず、以前の情報を保持している記録         |

## 6. CSVを出力する

1. 対象・フォルダ・検索・日数条件を設定する。
2. 「CSV出力」を押す。
3. ダウンロードされた`Tamaru-files.csv`を開く。

出力対象は現在の条件に合う全ファイルで、表示中の100行だけではない。フォルダの集計表ではなく、ファイルごとの一覧になる。CSVの並び順は初回検出日時・パス順で、画面の容量順とは異なる。

CSVはUTF-8・BOM付き。数式として解釈され得る名前には先頭に`'`が付く場合がある。ファイル名・社内パスが含まれるため、必要な管理者の間で扱う。

## 7. 日次収集と終了・再起動

- 日次収集はTamaruのプロセスが動いている間だけ実行される。ブラウザを閉じてもプロセスは止まらない。
- ローカルPCの電源断・スリープ中は収集しない。指定時刻を過ぎて起動した日は、未受付なら次の確認周期で当日分を収集する。
- 日次が失敗した場合、同日の自動再試行はない。原因を直して「今すぐ収集」を使う。
- 収集中は「今すぐ収集」と対象設定を変更できない。完了まで待つ。

終了は、収集完了を確認してからコンソールでCtrl+Cを押し、終了を待つ。収集が残っていれば処理完了まで待機する。共有の応答が止まると、終了にも時間がかかる場合がある。

再起動は同じEXE・同じ`--state`で行う。常駐タスクの場合は、作業中の自動再起動を抑止して停止し、作業後に元の起動設定へ戻す。`*.lock`が残っているだけでは異常ではないので、ロックファイルの削除で対処しない。

## 8. 管理者の追加とパスワード回復

「管理者管理」からID・表示名・パスワードを入力して追加する。全管理者が対象設定や他の管理者の変更もできるため、管理を任せる人だけを登録する。

無効化・パスワード再設定を行うと、その管理者の既存ログインは解除される。最後の有効な管理者は無効化できない。管理者の削除機能はない。

ログインできる管理者がいない場合は、実行PCのコンソールで同じ保存先を指定する。

```powershell
.\Tamaru.exe --state C:\TamaruData reset-password admin
```

対象IDは既存のIDに置き換える。パスワードを2回入力すると有効状態に戻る。既に管理者がいる保存先で`create-admin`を再実行しても追加はできない。

## 9. バックアップ・復元・更新

### 9.1 バックアップ

1. 現在の保存先を確認する。`--state`未指定なら、EXEと同じフォルダの`data`。
2. 収集完了を確認してTamaruを停止し、プロセスが終了したことを確認する。
3. 保存先フォルダ全体を新しいバックアップ先へコピーする。`app.sqlite3`・`inventory.sqlite3`・`settings.json`を含める。
4. 同じ保存先でTamaruを再起動する。

停止後に実行するコピー例:

```powershell
New-Item -ItemType Directory -Force -Path C:\TamaruBackup | Out-Null
$backupPath = Join-Path C:\TamaruBackup ('Tamaru-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath $backupPath) { throw 'バックアップ先が既に存在します。' }
Copy-Item -LiteralPath C:\TamaruData -Destination $backupPath -Recurse
```

バックアップ先のアクセス権も管理データと同様に限定する。稼働中のDBファイルだけをコピーする方法や、DBだけを別々の時点でコピーする方法は使わない。

### 9.2 復元

1. Tamaruを停止する。
2. 現在の保存先を残したまま、バックアップ全体を別の空の保存先へコピーする。既存フォルダへの混在コピーはしない。
3. 復元先を`--state`に指定して起動する。ローカルの起動例:

   ```powershell
   .\Tamaru.exe --state C:\TamaruData-Restored local
   ```

4. 管理者ログイン、対象設定、件数・初回検出日時を確認し、必要なら手動収集する。
5. 常駐タスクやショートカットを使っている場合は、その保存先も復元先へ合わせる。

手順2のコピー例。バックアップ名は実際のものに置き換え、復元先には存在しないフォルダ名を指定する。

```powershell
$restorePath = 'C:\TamaruData-Restored'
if (Test-Path -LiteralPath $restorePath) { throw '復元先が既に存在します。' }
Copy-Item -LiteralPath 'C:\TamaruBackup\Tamaru-20261028-120000' -Destination $restorePath -Recurse
```

初回検出日時と管理者設定は、バックアップ時点へ戻る。新しい空の保存先で起動するだけでは、以前の滞留日数を復元できない。

### 9.3 バージョン更新

1. 変更履歴を確認し、現在のEXEまたはソースと管理データをバックアップする。
2. 収集完了後に停止する。
3. アプリを新しい版へ差し替える。`data`や明示した管理データを新しい空のデータで上書きしない。
4. 以前と同じ保存先で起動する。EXEを別フォルダへ移す場合も、`--state`を明示するか、停止中に以前の`data`全体を引き継ぐ。
5. 画面下部の版、管理者ログイン、対象設定、収集結果を確認する。

旧版へ戻す必要がある場合は、旧アプリと更新前バックアップの組で復元する。更新後に記録した観測はそのバックアップには含まれない。

## 10. 困ったとき

| 症状                             | 確認と対処                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 起動直後に終了する               | PowerShellからEXEを起動してメッセージを確認。保存先の書き込み権限、ポート、同じ保存先の別プロセスを確認 |
| ポート使用中                     | 既存のTamaruを確認するか、`local --port 8766`などで別ポートを使う                                       |
| ブラウザが開かない               | コンソールのURLを手動で開く。EXEのコンソールが起動したままであることを確認                              |
| 別PCからローカル版へ接続できない | `local`はこのPC専用。別PCから使う場合はLAN向け設置手順へ切り替える                                      |
| 初回登録を毎回求められる         | 起動時の保存先を確認。カレントフォルダやEXEの移動で別の`data`を使っていないか確認                       |
| パスワードを忘れた               | 同じ保存先を指定して`reset-password ID`を実行                                                           |
| ログイン試行の制限が出る         | 15分程度待ち、ID・パスワードを確認して再試行                                                            |
| 対象を登録できない               | 絶対パス、100件以内、対象同士の親子重複、ツール・管理データとの重なりを確認                             |
| 一覧が空・件数が少ない           | 手動収集の結果、対象・検索・日数条件を確認。空フォルダは表示対象外                                      |
| 共有のエラー・未確認が出る       | 実行アカウントの共有アクセス、UNCパス、共有サーバーの稼働を確認。修正後に再収集                         |
| 自動収集されない                 | プロセスが起動中か、PCがスリープしていないか、日次の有効・時刻、当日の実行結果を確認                    |
| 収集や終了が長時間終わらない     | 共有の応答を確認。アプリには収集キャンセルがない。強制終了した場合は次の起動で中断記録を確認            |
| LANで403になる                   | HTTPS、接続元アドレス、プロキシの転送設定を設置手順で確認。Host不一致は400になる                        |
| 容量不足・DBが増えた             | 保存先の空き容量とバックアップを確認。履歴の自動削除はない。稼働中にDBを直接編集しない                  |

## 11. 初回利用後の確認

- 対象フォルダを手動収集し、想定するファイルの件数・容量・階層が出る。
- 「全ファイル一覧」の容量順と、対象を絞ったCSVを利用できる。
- 再起動しても同じ管理者・対象設定・初回検出日時を引き継ぐ。
- 日次収集を使う場合は、その時刻にプロセスが動いている。
- LAN常駐の場合は、ログオフ中・サーバー再起動後の共有収集と、停止中のバックアップ・復元を確認する。
